What is this? #

Sentinel is a Discord bot that you host yourself. Unlike those big public bots that are in millions of servers, Sentinel is designed to live in just one place: your server.

Because it's private, you don't have to share resources with anyone else. It's faster, more secure, and you have complete control over every single piece of data it handles.

Why self-host? #

Running your own bot might seem like extra work, but it pays off:

  • It's YOURS: You own the code, the data, and the database. No more worrying about a public bot going down or selling your data.
  • Zero Latency: Since it only serves your community, it responds instantly.
  • Custom Fit: Features are built specifically for the way a single community operates, rather than trying to please everyone.

What can it do? #

  • Keep things safe: Tools to warn, mute, and ban troublemakers.
  • Stop spam: Auto-filters for bad words, caps, and spamming.
  • Help your members: A private ticket system for support.
  • Fun stuff: XP and leveling to keep chat active.
  • Easy management: This dashboard you're looking at right now!

Recommended first hour #

  1. Finish installation and verify the bot comes online in your server.
  2. Open configuration and confirm serverID, OwnerID, botName, and invite links.
  3. Visit the web panel section to understand where moderation, users, analytics, and owner tools live.
  4. Turn on security basics like 2FA, recovery codes, and session review from your profile page.
  5. Test moderation, AutoMod, and tickets with a spare account before using them live.
  6. Check the analytics and automation tabs so you know where to monitor staff activity, jobs, and alerts later.

Using the Web Panel

Where to click, what each page does, and which role usually needs it.

Main pages #

  • Dashboard: Your general snapshot. Use it for a quick status check before digging deeper.
  • Moderator: The day-to-day workspace for punishments, user history, and case actions.
  • Admin: The control area for accounts, notes, lookups, and broader server management.
  • Owner: High-trust tools like system health, backups, security events, and deeper operations.
  • Profile: Personal account settings such as password, 2FA, recovery codes, Discord link, and active sessions.
  • Analytics: Trend reporting for moderation, verification, staff performance, emails, and alerts.

Best daily workflow #

  1. Start on the dashboard to see whether anything unusual happened overnight.
  2. Move to moderator tools if you need to warn, timeout, ban, or review a user's case history.
  3. Use admin lookup and notes when a member needs closer tracking or context for staff.
  4. Open analytics when you need trends, not just a single action.
  5. Use owner pages for backups, health checks, security review, or configuration-level decisions.

What to keep open #

🧭
Simple Rule Use the lightest page that solves the problem. Moderator pages are for action, analytics pages are for patterns, and owner pages are for high-trust system work.

If you're running the server live during busy hours, keep the dashboard, moderator panel, and your profile security tab nearby. Those three cover most real-time needs.

How do I install it?

Setting up your private bot is easier than you think.

Prerequisites #

Before we start, make sure you have these things ready:

  • Node.js v16+: This is the engine that runs javascript. If you don't have it, google "Install Node.js".
  • A Discord Application: Go to the Discord Developer Portal and make a new application. That's your bot!
  • MySQL Database: You'll need a database to store levels and warnings. Setting up XAMPP or installing MySQL server is usually the easiest way.

Setup Steps #

  1. Download the code and unzip it somewhere safe.
  2. Open a terminal in that folder and install the dependencies:
TERMINAL
npm install
  1. Now, let's create the database tables automatically:
TERMINAL
npm run setup
  1. Fill in your secrets (Token, DB password) in Config/credentials.env.
  2. Start the bot!
TERMINAL
npm start
💡
Pro Tip If you're running this on a VPS or server, use something like PM2 so it restarts if it crashes.

Configuring your Bot

Making sure Sentinel knows where its home is.

The Important Secrets #

Open up Config/credentials.env. This is where the magic keys live.
Do not share this file with anyone! It contains your bot token and database passwords.

🔐
Private File Treat Config/credentials.env like a vault. Keep real tokens, webhook secrets, SMTP passwords, and session keys out of screenshots, GitHub commits, and support messages. If one of these values leaks, rotate it before bringing the panel back online.
CONFIG/CREDENTIALS.ENV 
# Discord application
TOKEN=your_discord_bot_token
CLIENT_ID=your_application_id
GUILD_ID=your_server_id

# Database connection
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=your_mysql_user
MYSQL_PASSWORD=your_mysql_password
MYSQL_DATABASE=your_database_name

# Admin panel security
ENABLE_ADMIN_PANEL=true
ADMIN_PORT=3000
SESSION_SECRET=your_random_session_secret
TOTP_ENCRYPTION_KEY=your_random_totp_key

# Email and recovery
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=your_email_user
SMTP_PASS=your_email_password
ADMIN_EMAIL=owner@example.com
🤖

Discord Connection

These values link the bot to your Discord application and main guild.

  • TOKEN logs the bot into Discord.
  • CLIENT_ID is your application ID.
  • GUILD_ID keeps commands scoped to your server.
🗄️

Database Access

This group tells the bot and panel where your MySQL database lives and how to sign in.

  • Use a dedicated database user instead of root.
  • Keep the database name stable after setup.
  • Rotate the password if it is ever exposed.
🛡️

Panel Security

These values protect web sessions, encrypted 2FA secrets, and panel access.

  • SESSION_SECRET should be long and random.
  • TOTP_ENCRYPTION_KEY should never be reused elsewhere.
  • Only enable the panel after these are set.
📨

Email and Recovery

SMTP powers password recovery, owner alerts, and account security messages.

  • Use a real mailbox you control for ADMIN_EMAIL.
  • Test password reset and alert delivery after setup.
  • Prefer app passwords over your main mailbox password.
💡 If you are setting this up for the first time, fill in Discord and database values first, then add panel security keys, then finish SMTP once login and recovery are ready to test.
  • TOKEN, CLIENT_ID, and GUILD_ID connect the bot to your Discord application and primary server.
  • MYSQL_* values tell the bot and panel where your database lives and how to log into it.
  • SESSION_SECRET and TOTP_ENCRYPTION_KEY protect panel sessions and stored 2FA secrets. Generate long random values for both.
  • SMTP_* and ADMIN_EMAIL power recovery emails, alerts, and security notifications from the panel.
  • Webhook and moderation keys can live in this same file too. Keep optional integrations disabled until you have valid credentials ready.

General Settings #

Next, check Config/main.json. This is where you tell the bot which server it belongs to. Since Sentinel is private, it needs to know your Server ID (Guild ID) so it can ignore commands from anywhere else.

CONFIG/MAIN.JSON 
{
  "serverID": "1477214846381588561",
  "OwnerID": "255175516603154432",
  "ServerInvite": "SERVER_INVITE_LINK_HERE",
  "AppealLink": "https://your-domain.example/appeal",
  "WebsiteLink": "https://your-domain.example/",
  "githublink": "https://github.com/yourname/yourrepo",
  "websiteName": "Your Panel Name",
  "serverName": "Your Server Name",
  "PanelEmoji": "🛡️",
  "botName": "Your Bot Name",
  "Version": "7.2.0"
}
🏠

Guild Ownership

These values decide which Discord server the bot protects and which account gets owner-level panel access.

  • serverID should match your main Discord guild.
  • OwnerID should be your personal Discord ID, not the bot ID.
  • Wrong values here can make commands or owner pages appear unavailable.
🔗

Public Links

This group powers buttons, invite links, appeals, and web panel shortcuts shown throughout the bot and dashboard.

  • ServerInvite should point to your real guild invite.
  • WebsiteLink should be the main admin panel URL.
  • AppealLink should stay live if you use moderation appeals.
🎨

Branding

These fields shape how the bot and web panel look to users, including names shown in embeds, pages, and docs.

  • botName is the main display name used across the project.
  • websiteName controls the browser title and panel branding.
  • PanelEmoji gives the dashboard a recognizable icon.
🛰️

Release Metadata

This is the lightweight project identity block used for docs, changelogs, status text, and repository references.

  • serverName is the friendly label shown for your community.
  • githublink is useful for docs, credits, and source links.
  • Version should match your actual release so pages stay accurate.
🧭 Set serverID, OwnerID, botName, and WebsiteLink first. Those four values affect most of the bot behavior and panel branding right away.
  • serverID: Right-click your Discord server and use Copy ID from Developer Mode.
  • OwnerID: Use your own Discord account ID so the owner-only tools unlock correctly.
  • botName, websiteName, and PanelEmoji drive most of the visible branding across the bot and panel.
  • ServerInvite, WebsiteLink, and AppealLink should be checked after every domain, invite, or hosting change.
  • Version is worth updating when you ship panel or bot changes so docs and release labels stay trustworthy.

Moderation Tools

Keeping your server clean and friendly.

The Basics #

Most of the time, you'll be using these simple slash commands to manage users:

  • /warn @user [reason]: Adds a warning to their record.
  • /mute @user [duration] [reason]: Time-out a user so they can't type.
  • /kick @user [reason]: Kick them out (they can rejoin).
  • /ban @user [reason]: Ban them permanently.

Tracking Cases #

Sentinel remembers everything. Every time you warn or ban someone, it creates a Case ID. You can look these up later if you forget why someone was banned, or if they appeal.

COMMANDS
/case view [case_id]

AutoMod

Let the bot do the heavy lifting.

Protection Profiles #

Different days call for different rules. You can set up profiles like "relaxed" or "strict". If a raid happens, you can switch to "strict" instantly from the panel to stop the chaos.

What it filters #

  • Spammers: People sending messages too fast.
  • YELLING: Blocks messages with too many CAPS.
  • Bad Language: Automatically deletes words you've blacklisted.
  • Invite Links: Stops people from advertising other servers.

Leveling System

Give your active members some shine.

People love seeing numbers go up. Users earn XP just by chatting. You can control how fast they level up and add a cooldown so people don't spam just for points.

Rewards

You can set it up so users automatically get a cool role (like "Regular" or "Veteran") when they hit a certain level. Check Config/leveling.json to set the rewards.

Ticket System

Private support channels for your members.

Sometimes users need to talk to staff privately. Instead of messy DMs, they can open a ticket. Sentinel creates a private channel just for them and the staff team.

Cool Features

  • Transcripts: When you close a ticket, Sentinel saves a pretty HTML file of the whole conversation, just in case you need it later.
  • Categories: You can have different types of tickets, ranging from "Low", "Medium", to "High", depending on how important the user thinks the issue is.

Security & Access

How to keep your panel account and server tools locked down without overcomplicating it.

Start with your profile #

Your profile page is the main place to manage account safety. That includes password changes, two-factor authentication, recovery codes, active sessions, and Discord account linking.

  • Enable 2FA: This adds a second check after your password.
  • Save recovery codes: Keep them somewhere private in case you lose your authenticator app.
  • Review sessions: If a device or browser looks unfamiliar, revoke it.
  • Use a unique password: Never reuse the same password from Discord, email, or another site.

How login protection works #

The panel uses multiple checks during sign-in. Depending on your setup, this can include captcha challenges, two-factor verification, recovery codes, rate limits, and suspicious activity detection.

⚠️
Important Recovery codes are for emergencies, not normal daily sign-in. Once you use one, replace and store your fresh set again.

Practical safety checklist #

  • Do not share owner credentials with moderators or admins.
  • Use separate accounts for staff instead of shared logins.
  • Check security notifications when you see new-device or recovery activity.
  • Rotate passwords if a team member leaves or loses device access.
  • Keep Config/credentials.env private and out of public repos.

Analytics & Reports

Turn raw activity into useful decisions for moderation, staffing, and server health.

What analytics is good for #

  • Moderation trends: See if spam, punishments, or specific rule breaks are climbing.
  • Staff performance: Track who is handling actions consistently and where coverage is weak.
  • Verification funnels: Find out where users drop off during verification.
  • Email and alert health: Check whether security or operational notifications are being delivered.
  • System metrics: For owners, watch runtime health and background process stability.

How to read staff performance #

Use the staff performance section as a workload and coverage tool, not just a scoreboard. High totals can be good, but they can also mean one person is carrying too much. Very low totals may mean a staff member needs training.

Good review questions include:

  • Are actions spread across the team or concentrated on one person?
  • Are moderation spikes happening at the same times every week?
  • Do ticket or verification issues increase when certain staff are offline?

Use analytics with context #

📌
Best Practice Numbers explain patterns. They do not explain intent by themselves. Always compare charts with notes, case history, and what was happening in the server at the time.

Automation & Jobs

The quiet systems that keep the bot useful even when no one is manually watching it.

What runs automatically #

  • AutoMod checks: Filters spam, invites, bad words, and message patterns.
  • Scheduled jobs: Background tasks like maintenance, cleanup, reporting, or economy-related work.
  • Alerts: The panel can surface failures, suspicious activity, and owner-level notifications.
  • Backups: Owner tools can monitor and trigger database or server backup activity.
  • Auto-responses and flows: Things like verification, welcome flows, and support automation reduce manual work.

When to check jobs #

Open owner operations or analytics when something feels "quiet" in the wrong way. Missing emails, backups not running, no expected alerts, or stale analytics data often point to a background task that needs review.

USEFUL ENDPOINTS
GET /api/jobs POST /api/jobs/:id/retry GET /api/owner/system-metrics GET /api/alerts/active

Maintenance habits that save time #

  1. Check alerts before changing config so you do not hide the original problem.
  2. Retry failed jobs only after reading what the job was supposed to do.
  3. Keep backups recent before major configuration or permission changes.
  4. Review AutoMod simulations before switching strict rules on for a live server.

Who can do what?

Understanding the roles for this dashboard.

  • Owner: That's you. You can do literally everything.
  • Admin: Your right-hand people. They can change settings and ban people.
  • Moderator: The enforcers. They can warn, mute, and handle tickets, but they can't break the bot settings.

Admin / Developer API

These are the main internal endpoints used by the admin, moderator, analytics, and owner panels. Most of them require an authenticated session, and owner routes also require owner permissions.

Auth & Session

  • GET /api/csrf: Fetch a CSRF token for dashboard POST and DELETE requests.
  • GET /api/captcha/challenge: Get the login/register captcha challenge payload.
  • POST /api/login: Create an admin panel session.
  • POST /api/login/recovery: Login with a recovery code.
  • POST /api/logout: End the current session.
  • GET /api/account/info: Return the logged-in account summary used across the dashboard.

Moderation & Cases

  • GET /api/moderation/overview: Load overview cards for the moderator dashboard.
  • GET /api/moderation/recent-actions: Fetch the latest moderation actions.
  • POST /api/moderation/warn: Warn a member from the panel.
  • POST /api/moderation/ban: Ban a member from the panel.
  • POST /api/moderation/timeout: Timeout a member from the panel.
  • GET /api/moderation/case/:caseId: Look up a single moderation case.
  • GET /api/moderation/user/:userId/history: Fetch a member's moderation history.
  • GET /api/moderation/actions/search: Search moderation actions by query, type, and pagination.

Users, Notes & Admin Lookup

  • GET /api/admin/users: List panel users.
  • POST /api/admin/users: Create a new panel user.
  • PUT /api/admin/users/:userId: Update a panel user.
  • DELETE /api/admin/users/:userId: Remove a panel user.
  • GET /api/admin/users/:userId/details: Load extended account details for a panel user.
  • GET /api/admin/search-users-advanced: Advanced user search with filters and pagination.
  • GET /api/admin/system/lookup/:query: Resolve a user, account, or moderation profile from a lookup string.
  • POST /api/admin/system/lookup/:userId/notes: Save lookup notes for a tracked member.
  • GET /api/members/:userId/notes: Read stored member notes.
  • POST /api/members/:userId/notes: Update stored member notes.

Analytics & Intelligence

  • GET /api/stats: Load global bot/dashboard stats.
  • GET /api/stats/today: Fetch today's activity totals.
  • GET /api/dashboard/all: Load dashboard summary data in one request.
  • GET /api/moderation/analytics: Return moderation trend data.
  • GET /api/moderation/intelligence: Fetch moderation intelligence and risk-style insights.
  • GET /api/owner/verification-analytics: Verification funnel metrics for the owner analytics page.
  • GET /api/owner/staff-performance-analytics: Staff performance leaderboard and action totals.
  • GET /api/owner/email-analytics: Email delivery, failures, and template trends.
  • GET /api/owner/alert-settings-analytics: Alert configuration and trigger analytics.

Owner Controls & Operations

  • GET /api/owner/system-metrics: System usage and runtime metrics for owner dashboards.
  • GET /api/owner/system-stats: Owner-facing platform stats summary.
  • GET /api/jobs: View scheduled jobs and statuses.
  • POST /api/jobs/:id/retry: Retry a failed scheduled job.
  • GET /api/automod/config: Read the active AutoMod config.
  • POST /api/automod/config: Update AutoMod config or profiles.
  • POST /api/automod/simulate: Run a test message through the AutoMod evaluator.
  • GET /api/automod/advanced: Advanced AutoMod review queue and trends.
  • POST /api/automod/workflow/:violationId: Update the review workflow for an AutoMod violation.

Backups, Security & Alerts

  • GET /api/owner/backups/status: Read database backup status.
  • POST /api/owner/backups/run: Trigger a database backup job.
  • GET /api/owner/server-backups/status: Read server backup status.
  • POST /api/owner/server-backups/restore: Start a server backup restore operation.
  • GET /api/system/health: Check owner-visible health status for the panel and bot environment.
  • GET /api/security/events: Query recorded security events for the owner panel.
  • GET /api/alerts/active: List currently active owner alerts.
  • POST /api/alerts/:id/resolve: Resolve an active alert.

Help! It's broken!

Common problems and how to fix them.

The Big One #

⚠️
Remember Sentinel is a private bot. It only works in the server ID you put in the config. If you invite it to a second server, it will just sit there and ignore everyone.

It's online, but ignoring me? #

If the console says "Bot is ready!" but commands aren't working:

  • Check Intents: Did you enable "Privileged Intents" (the toggles) in the Discord Developer Portal? You need those.
  • Check Roles: Is the bot's role above the person you're trying to ban? It can't moderate people higher than itself.

Where are my slash commands? #

Sometimes Discord takes a minute. Since Sentinel registers commands instantly to your specific guild ID, they should be there. Try restarting the bot. If that fails, kick the bot and re-invite it.
