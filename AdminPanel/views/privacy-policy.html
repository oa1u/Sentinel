Privacy Policy

Clear information about what the bot and dashboard collect, why the data is used, and what security protections are in place.

📌 The Basics

This Privacy Policy explains how ("we", "us") handles information when you use the Discord bot, the web dashboard, and the related admin APIs. We built these tools to help run communities and protect accounts, not to collect unnecessary data.

By using the bot, dashboard, or linked security features, you agree to the data handling described here.

What this covers: Discord account details used for commands and moderation, dashboard account data, session and security information, optional analytics, backups, and support or recovery flows.

What this does not mean: We do not claim ownership of your Discord content, and we do not sell personal data.

📩 Got Questions? Ask in the GitHub Repo.

📦 What We Collect
  • Account and Profile Data: We may store usernames, display names, Discord IDs, linked Discord account details, avatars, email addresses, panel roles, and profile preferences so accounts can sign in and use the dashboard safely.
  • Authentication and Session Data: When you use the web panel, we process session cookies, CSRF tokens, IP information, browser or device details, login timestamps, activity timestamps, captcha challenge state, and two-factor authentication challenge data.
  • Security and Recovery Data: If you enable security features, we may store encrypted two-factor secrets, recovery code metadata, security approval state for sensitive actions, active session information, Discord trust state, and security event history.
  • Discord and Server Configuration: We store server IDs, channel IDs, role IDs, welcome settings, moderation settings, verification settings, auto-responder rules, analytics preferences, and other configuration required for the bot and dashboard to function.
  • Moderation and Operational Records: We may store case logs, warnings, punishments, notes, appeals, verification outcomes, ticket activity, and optional moderation history so staff can manage a server consistently.
  • Messages and Content Data: We do not keep full chat logs by default. Specific message content may be processed or stored when a command is used, when a feature explicitly requires it, when logging is enabled, or when content is needed for moderation, verification, or anti-abuse features.
  • Analytics and Diagnostic Data: We may collect command usage counts, moderation activity totals, verification analytics, email delivery analytics, alert settings analytics, error details, and performance information to keep the service stable and useful.
  • Backup Data: If backups are enabled, stored backup files can include server configuration, moderation data, and other operational records needed for recovery and restore workflows.
🎯 How We Use It
  • To Run Core Features: Data is used to execute commands, apply moderation actions, run verification flows, manage tickets, automate roles, and power the dashboard.
  • To Secure Accounts and the Panel: Session data, IP data, captcha state, CSRF protection, rate limiting, login telemetry, device checks, Discord link trust, and two-factor verification are used to reduce abuse and unauthorized access.
  • To Deliver Notifications: We may send security alerts, recovery emails, login notices, moderation notices, or Discord direct messages when a feature depends on those notifications.
  • To Improve Reliability: Diagnostic logs, analytics, delivery metrics, and error reports help us detect failures, tune features, and investigate issues.
  • To Support Recovery and Restore: Backups, restore manifests, and retention settings are used to recover configuration or operational data when the owner triggers those tools.
  • To Meet Platform and Legal Requirements: We may process data to comply with Discord requirements, security obligations, abuse prevention needs, and valid legal requests.
🤝 Sharing, Storage, and Retention
  • No Data Sales: We do not sell personal data or trade account information for advertising purposes.
  • Service Providers: Data may be processed by infrastructure providers that make the bot and dashboard work, such as hosting, database, email, backup, and Discord platform services.
  • Server Owner Visibility: Server owners and staff may be able to view moderation records, tickets, verification results, analytics, and settings that belong to their own server because those tools are part of the service they manage.
  • Dashboard Storage: Web panel session data is stored for authentication and expires based on panel security policy, inactivity timeouts, or logout.
  • Security Records: Security alerts, login history, approval states, and other protection-related data may be retained while needed for account safety, fraud review, and abuse prevention.
  • Backups and Restore Files: Backup files and manifests remain stored until rotation, replacement, manual deletion, or configuration changes remove them.
  • Logs and Analytics: Operational logs and analytics may be kept for troubleshooting, service monitoring, and reporting, then rotated or deleted over time.
🧯 Keeping It Safe
  • Password and Secret Protection: Passwords are not stored as plain text, and sensitive secrets such as two-factor material are protected with encryption and server-side controls.
  • Session Protections: The panel uses authenticated sessions, CSRF protection, timeout policies, same-origin checks, and cookie controls to reduce unauthorized use.
  • Abuse Defenses: Captcha challenges, login throttling, identifier-based rate limiting, security signals, suspicious-device detection, and high-risk action approvals help block brute-force and misuse.
  • Access Control: Dashboard access is role-based. Owner, admin, moderator, and user permissions are separated, and sensitive actions can require extra verification.
  • Security Notifications: The service can generate email or Discord security alerts for events such as logins, new devices, password changes, recovery usage, and two-factor updates.
  • Operational Safeguards: Backups, manifests, restore checks, audit trails, and server-side logging are used to help recover from mistakes and investigate incidents.
🛠️ Your Controls and Choices
  • Account Security Settings: You can manage your password, enable or disable two-factor authentication, regenerate recovery codes, and review parts of your profile from the dashboard.
  • Session and Access Control: You can sign out, expire panel sessions, and remove access by changing credentials or using built-in security tools.
  • Discord Linking Controls: If Discord account linking is enabled, you can link or unlink your Discord account subject to the panel's security requirements.
  • Server-Level Controls: Server owners decide which moderation, logging, analytics, backup, and automation features are turned on for their own server.
  • Questions or Requests: If you need clarification, believe data should be removed, or need help with a privacy or security issue, contact the server owner or open an issue through the project contact channel listed on this page.
